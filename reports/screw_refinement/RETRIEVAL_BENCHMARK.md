# CPU 检索微基准：直接差分与 float64 GEMM

2026-10-09 在本机 Intel i5-1130G7 上实际完成。下表来自当时的三次测量记录，保存文档时没有重新运行。完整数字与环境在 [JSON](RETRIEVAL_BENCHMARK.json)。

只使用 MVTec AD **螺丝正常训练图**：`train/good/000.png–019.png` 为每个位置的 20 个参考，`020.png` 为查询；没有读取测试图。固定一个查询与库、1 个 PyTorch CPU 线程、空间半径 3，预热后交替执行两种实现三次。原实现 `spatial_distances` 使用 chunk 8。新版 `spatial_distances_gemm` 使用 float64 大矩阵乘法选择邻域内最近参考，然后以原 float32 直接差分计算最终距离。

| 尺寸 | 原直接差分三次 / ms | GEMM 三次 / ms | 中位数加速 | 最大距离差 / 自身距离 |
|---|---|---|---:|---|
| 224 | 503.64 / 507.28 / 546.54 | 76.23 / 75.71 / 80.17 | 6.65 倍 | 0 / 0 |
| 336 | 1311.00 / 1331.76 / 1355.43 | 303.45 / 337.94 / 322.02 | 4.14 倍 | 0 / 0 |

首次 GEMM 含建 float64 库、范数和位置掩码：224 为 214.04 ms，336 为 416.14 ms。预处理和骨干特征提取不计入上述检索耗时。真实库分别是 `14×14×20×384` 和 `21×21×20×384`。

float64 参考库分别约 11.48 / 25.84 MiB，距离输出分别约 5.86 / 29.68 MiB。32 MiB 预算只约束距离输出，**不是进程峰值内存**。准备缓存最多三项，并检查同一 tensor 对象及 mutation version；没有版本计数的 inference tensor 不复用缓存。

环境为 PyTorch 2.14.0+cpu、torchvision 0.29.0+cpu、timm 1.0.30、NumPy 1.26.4、Pillow 12.3.0；权重与预处理契约见 JSON。相关模块 14 项测试全部通过，覆盖随机/边界/重复向量、自身距离、低内存预算分块、缓存变更失效和容量限制。

这是每个尺寸一个正常查询、三次重复的微基准，不能当作整个测试集或其他 CPU 上的稳定加速倍数。为保证同条件，336 探针也使用半径 3；正式 raw336 候选使用半径 4。结果不说明检测精度有变化，也不包含模型加载、PNG 输出和网页开销。
