# DINOv3／DINOSaur 项目：简历与面试讲解

项目定位是工业异常检测的本机研究与工程实现。围绕旧 ResNet18 特征在螺丝类别表现不足的问题，复现 2026 DINOSaur 的核心设计：冻结 DINOv3 ViT-S/16、空间索引 coreset 特征库、邻域限制最近邻评分。它属于近期方法的 CPU 适配与实证分析，不是提出一个已证明领先的新算法，也不是完整复现论文的持续学习 benchmark。

方法与材料来源分开记录：[DINOv3 模型卡](https://huggingface.co/timm/vit_small_patch16_dinov3.lvd1689m)及权重使用官方自定义 DINOv3 License，不属于 MIT／Apache 模型许可；[MVTec AD 原图及衍生可视化](https://www.mvtec.com/research-teaching/datasets/mvtec-ad)遵循 CC BY-NC-SA 4.0。项目自编代码许可不替代这些材料条款。

## 一分钟讲解

“我先实现了 ResNet18 局部特征最近邻基线。瓶口测试效果很好，但螺丝接近随机，说明单类别高分不足以证明方法有效。我随后研究并实现 2026 DINOSaur 的核心设计，用冻结 DINOv3 提取更强的视觉特征，同时为特征库保存空间位置，测试 patch 只与邻域内的正常 patch 比较。这样既利用物体布局，也控制正常背景特征干扰。我用四类别、固定划分和多个建库种子验证，再分别去掉 coreset 和空间约束，看性能、误报、定位与 CPU 成本是否符合预期。结果中改善和失败都会保留。”

讲解最后应补充实际表格中的改善类别和退化类别，不能预先承诺换基础模型必然变好。

## 面试常见问题

**为什么不训练一个二分类器？** 正常训练集不需要缺陷标签。真实工业场景中异常类型可能不断变化，学习正常特征分布能对未见过的缺陷输出异常程度；代价是阈值、正常样本覆盖和拍摄域变化仍会影响误报。

**DINOv3 比 ResNet18 多了什么？** 特征来自更近期的大规模自监督视觉基础模型，patch token 表示可用于密集对应和异常定位。模型在通用视觉任务上的能力不等于本项目一定更好，因此需要同一测试集上的实际对照。

**为什么保存空间位置？** 对布局稳定的工业俯视图，某个位置出现的特征应优先与附近正常位置比较。完全无空间限制可能用其他位置的相似特征掩盖异常；严格固定位置又容易把正常位移误判成异常。半径为零、半径三与无限制的对照能说明这个取舍。旋转明显、尺度变化大的类别可能对该约束不友好，应从结果验证。

**为什么用 coreset？** 正常训练 patch 数量多，保存全部向量会增加存储与检索成本。k-center 用覆盖特征空间的代表向量建库；与同预算随机采样比较，才能判断覆盖策略是否有效。不能只报告压缩后的小库而不记录提取与建库时间。

**阈值怎么定？** 仅正常训练样本参与建库和校准，两组互斥。用 held-out 正常分数的第 95 百分位作为阈值，不读取测试缺陷标签选 F1 最优阈值。由于类别分布和样本数量有限，它不保证实际误报率一定为 5%。

**3 个 seed 说明什么？** 数据划分不变，只改变 coreset 的随机起点等建库随机性。mean±std 说明模型对这部分随机性的稳定程度，不能当作跨工厂、跨相机或独立测试集的置信区间。

**持续加入类别时，模型如何知道图片属于哪个类别？** 主方案的逐类别对照使用已知类别库；另一个实际序列实验用训练正常图的 CLS 均值作为类别原型，选择最近原型后评分。每阶段同时记录路由准确率与异常检测 AUROC。新增原型可能改变旧图路由，即使旧库不变，输出也可能退化，因此不能由“没有训练”直接推出“实测零遗忘”。

**为什么不能说“复现论文成绩”？** 本机 CPU 使用 timm 公共 DINOv3 权重适配，按模型卡将 RoPE periods 经 bf16→float32 截断以匹配原精度，但接口替代仍不宣称逐位一致；测试类别、分辨率、预算和运行硬件也有限。当前复现的是核心检测机制。整篇论文还包含持续学习、连续漂移、逻辑异常与边缘硬件评测，只有实际执行并对齐协议才能声称复现对应部分。

**最值得继续改的地方是什么？** 根据真实错误样本选择一个问题，例如旋转／尺度变化导致空间匹配失败、背景特征干扰或局部细小缺陷被低分辨率抹掉。改进前先固定独立验证协议，不能反复观察测试结果后调参数再把同一测试集称为独立验证。
